# 独立测试部署与手机安全访问

## 部署约束

不修改现有容器、Nginx、数据库或 80/443。使用独立目录、独立进程、loopback 18791，无 Docker 依赖。密码通过权限 0600 的服务环境文件注入（父目录 0700）；代码不自动读取任意凭据文件，不输出凭据。仓库内不要创建真实 .env、usage-private.json 或 Codex auth.json。

首次测试默认 CODEX_ENABLED=0、不设置管理员密钥，只验证未连接状态。不得为获得通过而伪造数据。部署必须先跑 node --test 与 npm run check；启动后验证：无授权 401、正确授权 200、跨域 403、写入 405、路径越界 404、响应 no-store，且监听仅为 127.0.0.1。

## 私有手机访问方案（未启用）

首选现有经过用户授权的私有 VPN，或独立受身份保护的 HTTPS 网关。网关必须在转发前鉴权、启用 TLS、不缓存页面或 JSON，并只转发至 loopback 服务；若代理改写 Host，应固定为 `127.0.0.1:18791`，剥离客户端伪造的转发头。浏览器 Origin / Host 策略须通过实际网关验收后才能开放；当前后端默认拒绝远程 Origin，不能直接宣称任意反向代理都可用。

也可用受控 SSH 加密本地端口转发供测试设备访问。手机须具备可靠的受控隧道，不可把本机端口转发为匿名公共 URL。Basic 密码仅在加密通道内传输。

本项目不配置 VPN、不开放防火墙、不创建匿名公网隧道、不更改生产 Nginx。不提供没有保护的手机测试 URL；没有安全入口时仅交付 loopback 验证结果，并将远程手机验收列为阻塞。

## 停止与清理

只停止独立测试进程（以该测试目录记录的 PID 和命令为准），不要批量杀死 node 进程。删除独立测试目录即可清除测试密码与日志；采集结果仅在内存。公开 Pages 的 usage.json 必须始终保持未连接占位，CI 会校验。

旧 V1 手动记录界面已撤下。旧 service worker 在更新时删除 gpt-usage-v1 缓存并注销；完全离线的旧客户端须联网更新后才能得到新界面。项目不会主动读取或上传旧 localStorage。
