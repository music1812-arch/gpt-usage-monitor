# V2 最终技术核查与交付边界

日期：2026-11-03；开发分支 feat/v2-private-usage；PR #2 保留打开，未合并或宣称正式上线。

## 已审核范围

逐文件审核 PR 相对 main 的全部变更，包括五个后端模块、前端脚本 / HTML、公开占位 JSON、service worker / manifest、测试、CI、依赖锁文件及交付文档。

- 官方额度与 API 统计分离，窗口以服务端返回为准，不根据任务数猜测。
- Codex 仅调用 initialize / account/read / account/rateLimits/read，不主动登录、推理或修改额度；对子进程移除监控密码和 API 管理员密钥。
- 服务器只绑定 loopback；固定文件白名单、密码验证、来源限制、限频、CSP / HSTS / no-store。不把认证值或原始上游错误写入响应 / 日志。
- 私人结果只保存在进程内存；公开 Pages 数据只允许精确的空占位结构。CI 拒绝额外字段及被跟踪的凭据文件 / 私人快照。
- GitHub Pages 发布的是 main，不会因为 PR 中有私有服务代码就提供私有服务；独立服务和公开静态站是不同交付路径。
- 访问密码是独立应用密码，保存在仓库外受保护文件。标准 CLI 登录若成功可能由官方 CLI 保管凭据；V2 没有自动登录或读取 / 导出认证文件的逻辑。

## 本轮发现与修复

实测临时隧道的 HTTP 入口此前返回 401 密码挑战。已在应用层让受信网关标记的 HTTP 请求先跳转到固定 HTTPS origin，不发送密码挑战；禁止把客户端请求 Host 作为跳转目标。该机制要求独立网关覆盖 X-Forwarded-Proto，不能部署在直接信任公网客户端转发头的配置中。直接 loopback 探测仍可使用 HTTP，不作为公网地址提供。

另外将静态文件路由限定为对象自身属性，避免原型属性路径进入读取逻辑；加强公开 usage.json 的精确结构检查，防止添加私人元数据却通过 CI。为 HTTP 跳转 / 原型路径增加回归测试。

## 验证口径

- 本轮完整测试基线 26/26 通过；修复后为 27/27。运行 npm run check、npm test、Chromium / WebKit 手机测试，最终 CI 以 PR 上最新提交结果为准。
- 手机自动化覆盖 390px / 320px、鉴权加载、无手动输入、无水平溢出、异常与恢复；这是浏览器引擎测试，不代替实体 iPhone 验收。用户已确认既有 HTTPS 页面可在手机打开。
- 实际服务验证覆盖 TLS、无授权拒绝、正确授权、私有页面无嵌入密码、no-store、HSTS、来源状态及后台刷新时间变化。未取得成功额度时 observedAt 保持空，不把 lastAttemptAt 当作成功采集时间。
- 对本地全部可见 Git 历史进行真实监控密码 / 常见 API Key / 私钥特征检查；本轮检查未发现匹配。此检查不等于能证明任意未知秘密绝不存在。
- 公开站 usage.json 与精确空占位比对；公开文件与私人运行时目录分离，测试截图不提交。
